THE ARCHITECTURE TO PROVE — a PURE SYNC DECISION CORE + a thin async shell. This split is the whole point: all the hard concurrency decisions happen in synchronized, non-async code that can be exhaustively tested (and loom-checked); async only wraps the blocking awaits.

1. `RouteInbox` (the sync core, behind ONE Mutex — every method O(1), NEVER async):
   - fields: `admission: Admission {Open,Closing,Closed}`, `queue: VecDeque<u64>` (corrs FIFO), `slots: HashMap<u64, Slot>`, plus whatever counts you need.
   - `Slot { frame: Frame, state: SlotState }`, `enum SlotState { Queued, Sending{cancelled: bool}, Delivered }`.
     NOTE the council fix for N2: the post-acquire pre-send state is `Sending` (NOT the v2 doc's `Claimed`), and a CANCEL that arrives while a corr is `Sending` sets `cancelled=true` and the drain checks it AFTER the send-decision under lock — see the state machine below.
   - Methods (all sync, all take &mut self under the caller's held lock, all O(1)):
     - `push_request(corr, frame) -> PushOutcome` : N4 — if `slots` already contains corr, return `PushOutcome::DuplicateCorr` (caller synthesizes a protocol error; do NOT overwrite — silent overwrite is the N4 leak). If admission != Open -> `Rejected(Closing/Closed)`. If over depth cap -> `Backpressure`. Else insert Queued + push_back, return `Admitted`.
     - `pop_for_dispatch() -> Option<u64>` : N1 — this is the ATOMIC pop+claim. Pop front corr, transition its slot Queued->Sending{cancelled:false}, return corr. If the popped corr has no slot (shouldn't happen) handle explicitly, never index-panic. This single method under one lock closes N1's two-lock gap: there is NO window between "removed from queue" and "marked Sending".
     - `on_cancel(corr) -> CancelDecision` : match slot state — Queued -> remove slot, return `SynthesizeCancelled` (never acquired credit). Sending{..} -> set cancelled=true, return `DeferredToDrain` (drain will roll back post-acquire, before send). Delivered -> return `ForwardToModule` (module owns the terminal). None -> `ForwardToModule` (unknown/already-settled; module no-ops).
     - `commit_delivered(corr) -> CommitDecision` : called by the drain AFTER acquire succeeds, under lock, BEFORE the actual module send. If slot is Sending{cancelled:true} OR admission==Closed -> remove slot, return `RollbackCancelled` (drain releases credit via the token + synthesizes cancelled). Else set state=Delivered, return `Proceed` (N5-adjacent: Delivered recorded before the send await happens).
     - `on_terminal(corr) -> bool` (R11 exactly-once): if slot exists AND state==Delivered -> remove, return true (release credit). Else return false (duplicate/late/unknown -> forward but credit-inert). This composes with ChannelFlow's existing CAS guard; prove BOTH together (test T15 with TWO concurrent in-flight so the CAS cannot mask the double-release).
     - teardown transitions: `begin_closing()`, `finish_closed() -> Vec<u64>` (drain remaining queued corrs to synthesize/drop).
