## Scope: crates/subc-core ONLY (plus its tests). Do not touch clients or subc-mcp.

Implement spec §3 in the daemon:

1. **Epoch counters + minting at reservation** (§3.2): per client-connection and per module-endpoint `slot → last_epoch` maps in ForwardingInner. Epoch 0 reserved (channel-0); first binding of a slot = 1. Reservation (`begin_route_bind_relay_*`) increments BOTH slots' counters and stores both epochs in `PendingRouteBindRelay`. Aborted reservations consume the increment (never returned).
2. **Synchronous commit-on-ack + client publication ordering** (§3.2): extract `commit_route_locked(&mut ForwardingInner, ...)`. BEFORE relaying route.bind, acquire an owned client-egress permit (without holding the forwarding lock) and store it in the pending reservation with a PREBUILT RouteOpen response (original client corr + negotiated version). The Accepted transition performs commit + consumes the permit (table publication and response-queue insertion with NO unlock between). Rejected/Aborted releases the permit exactly once. Ordering guarantee is per-handle.
3. **Single-winner bind resolution** (§3.2): one write-locked `Pending → Committed | Aborted | Rejected` transition; arbiters are daemon-side only (module reply, relay deadline, drain, connection death); winner acts, losers observe. Apply the same arbitration to module-control RPCs (their completion path today ignores the stored deadline — fix that).
4. **Relay validation + rewrite** (§3.3 layer 1): `lookup_data_route` callers validate `frame.epoch == binding.<side>_epoch`; mismatch → DROP (debug log + counter, never an Error); match → forward, rewriting channel AND epoch to the other side's values. No-binding behavior unchanged (unknown_channel Error for Requests stamps the INGRESS epoch; mismatched frames produce no Error at all). Direction-agnostic: identical validation both directions, all frame types including pure-header (Cancel/Goodbye/Ping/Pong).
5. **Epoch-fenced release** (§3.3): frame-driven route-scoped release becomes write-locked compare-and-remove taking expected_epoch (stale/absent/removed outcomes). Peer-notification GOODBYEs emitted only from actually-removed bindings, stamped with each binding's epochs.
6. **Owner-scoped teardown** (§3.3): cleanup_connection = mark-closing + remove bindings/reservations in one locked transition. Endpoint drain stays two-phase per the spec text (phase 1: mark draining + close Request admission on live bindings + abort reservations, one locked transition; quiescence; phase 2: remove then-current live bindings in one locked batch). The persistent marks reject allocation/commit between phases.
7. **Publication-keyed escalation** (§3.3): `last_published_epoch` per client slot, advanced ONLY by the locked commit+RouteOpen-enqueue transition. `escalate_client_delivery_failure(connection, channel, expected_epoch)`: close iff `last_published_epoch == expected_epoch`; aborted/uncommitted successors do NOT suppress, committed/published successors DO. Mark-closing under the forwarding lock BEFORE signaling the close registry; allocation/commit reject marked connections. Escalation call sites retain the failing frame's epoch — add epoch fields to `RouteBinding`, `GoodbyeTarget`, and the router error/synthesis paths so no daemon-originated frame goes out unstamped (cleanup GOODBYEs, module-death propagation, drain GOODBYEs, abort-bind GOODBYEs all stamped per spec).
8. **Reserved-slot ingress** (§3.3): client Request on a reserved-uncommitted slot → unknown_channel Error stamped with ingress epoch; every other frame either direction → drop.
9. **Route-referencing control ops** (§3.3.1): RouteStatus push validated (channel, route_epoch) atomically against live binding/reservation under the lock — stale drops, never cached. RoutePoll answered from ONE locked snapshot (validation + binding + module identity + cached status in the same critical section); status cache keyed by full client handle (or exact-generation cleared); absent/stale per spec (status→null/null, liveness→null/false, always echoing the REQUESTED handle).
10. **Channel-0 corr hygiene** (§3.3.1): ONE shared monotonic allocator per target connection/endpoint for ALL daemon-originated channel-0 requests (bind relays + module-control RPCs — today two independent wrapping cursors; unify). Never reuse within a connection lifetime; on exhaustion close the connection. Late responses to settled corrs drop.
11. **Allocator** (§3.4): never assigns a slot with a live binding OR live reservation; a slot whose epoch reaches u32::MAX takes at most that one final reservation then is ineligible (skip) for the connection/endpoint lifetime.
12. **Exact-version handshake** (§2): `negotiate_version` clamping removed — HELLO with protocol_ver != 2 rejected loudly.
13. **Watchdog + internal callers**: the self-request path and any internal frame construction stamp epoch 0 on channel 0 and real epochs on route frames.
