## Scope: crates/subc-client-rs ONLY.

1. **RouteHandle** (§3.2.1): public immutable `RouteHandle { channel: u16, epoch: u32 }` + opaque connection token (the existing `RouteState.generation` IS this token — unify, don't duplicate). Every route-scoped consumer op (call, subscribe, cancel, close_route) and all managed-route cache state moves from bare channel to handle. Ops with a token mismatching the current connection generation fail locally (typed error), emitting no frame. Only channel+epoch ever serialize.
2. **Consumer** (consumer.rs): route.open consumes route_epoch; the dispatcher installs the handle into its channel→epoch map BEFORE resolving the open caller and before reading the next frame (§3.2). Reader task validates every nonzero-channel ingress frame against the map BEFORE dispatch/lifecycle effect — mismatch/unknown → silent drop + counter (this overrides any current unknown-channel reaction; Request/Cancel/Goodbye alike). In-flight keyed by (channel, epoch, corr). GOODBYE eviction + unknown_channel single-retry stay, handle-keyed. Reconnect: reopened routes get FRESH handles (new token); no stale handle can act on the new connection.
3. **Late-RouteOpen cleanup** (§3.2): locally-timed-out route.open retains its corr identity; a late successful RouteOpen response is NOT dropped — immediately close the returned handle with GOODBYE (escalate to connection close if the GOODBYE cannot be queued). Never orphan.
4. **Serve side** (lib.rs): `on_bind` stays decision-only (verify no SDK-side emission currently precedes the ack; the ack epoch comes from RouteBind.epoch). After Accept: queue ack, install handle in the endpoint map, then invoke a NEW optional `on_bound(&RouteHandle)` handler hook (default no-op) where route egress legally begins. Rejection/ack-queue-failure: handle never installed, on_bound not invoked, handler cleanup invoked directly with the tentative handle. Serve loop validates ingress per layer 2 (unknown/mismatched slots silently dropped — today handle_frame dispatches any nonzero Request; that ends) and stamps the module-side epoch on all egress (Response/StreamData/StreamEnd/Error + reverse Requests). Reverse-reply contexts (`emit`, request contexts) retain the full handle — a reverse reply never looks up "the current epoch" at reply time.
5. **Corr hygiene** (§3.3.1): all channel-0 corrs this SDK originates come from ONE monotonic allocator with NO reuse for the connection lifetime — fix the current saturate-at-u64::MAX behavior in consumer.rs (send_request) and the wrapping next_module_control_corr: on exhaustion, close + reconnect. Late responses to settled corrs drop.
6. **Admission class**: optional per-call option (default NORMAL) stamping bits4-5 on egress; module serve emit paths accept an optional class for StreamData/Push (SHEDDABLE legality is enforced at the protocol decode layer — just plumb the option).
7. **RoutePoll**: carry route_epoch; match the echoed handle before settling/caching.
8. **F4 fix rides along** (pre-existing SDK bug queued for this release): `SubcConsumer::call` can park on the route flow-control semaphore past its own deadline because the deadline check happens after acquisition — make permit acquisition deadline-aware (acquire with timeout bounded by the call deadline).
