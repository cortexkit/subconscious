# Changelog

## Unreleased

- A mutating `callManagement` or `callManagementTracked` call whose session ends before any answer arrives no longer throws `FedFailure.disconnected`, whatever ended the session (a reset, `suspend()` or `disconnect()`). An app reads that as "nothing happened" and may tell the person it is safe to send again, when the computer may already have received and run the change. If the request reached the transport, even when the write failed partway, the call now throws `FedFailure.indeterminateMutation` and is left for the next session to ask the computer about, as before. If the library can prove the request never left the device, the call throws `FedFailure.mutationNotSent(code: "session_lost_before_write")`, is settled not sent on the device at once, and is safe to send again. Proof means it was still waiting to write when the session was disconnected, or an earlier write on that transport had failed. `session_lost_before_write` is a code local to this library and never appears on the wire. Tracked calls still carry the effect id on both paths, and `settledOutcome(of:)` returns the same answer later. After a write on a session's transport fails, that session writes nothing more: the failed write may have left part of a frame, which would garble anything sent after it. Read-only calls still throw `FedFailure.disconnected` (or `.suspended` after `suspend()`), and a store that closes under the calls still throws `FedStateStoreClosed`. The README's lost-reply section is corrected to match. No public enum gains a case and no public signature changes.

- Add optional `preSendCheck` to every `callManagement` and `callManagementTracked` form, including payload calls. It runs synchronously on the session executor after admission and the frame-writer wait, immediately before each request write attempt. A first-write veto writes nothing, durably settles a mutation as not sent and throws the new standalone `FedPreSendVetoed`; a veto after a possibly delivered write settles uncertain and throws `FedFailure.indeterminateMutation`, without writing again. Tracked calls wrap the same errors and retain the settlement for `settledOutcome(of:)` (`mutationNotSent` with code `fed_pre_send_vetoed` for a first-write veto). No existing public enum gains a case; omitting the check preserves existing behavior and an accepting check leaves the wire bytes unchanged.

- Add confirm-marked fed operations and the App Attest provider for operator elevation. `FedCatalogOperation` gains `confirm` (default `false`), parsed from `"confirm": true` and exposed through `lookupOperation` beside `payload?.maxBytes`; absent means `false` and any other value drops that operation, as a malformed `delivery` does. No public enum gains a case and existing construction keeps compiling. Add `FedAppAttestProvider` (pairing attestation plus per-session assertion over double-SHA-256 client-data hashes), sent once after the pairing handshake and as the first frame after hello on ordinary sessions only; share sessions never carry one. A missing or failing provider sends nothing and never fails the pairing or session. New tests pin the challenge bytes and exact frame bytes.

- Add `SubcFedClient.callManagementTracked(...)` (same three forms and behaviour as `callManagement`) and `SubcFedClient.settledOutcome(of:timeout:)`, so the app can recover the outcome of a module mutation whose reply was lost instead of reporting "couldn't confirm" or calling the module again. A tracked call returns `FedTrackedCallResult` (body plus an optional effect id, nil for a successful read-only query) and throws `FedTrackedCallError` (the unchanged `callManagement` error plus the effect id, nil for read-only queries and calls refused before an id was assigned). `settledOutcome` returns the settled outcome exactly as the call would have: the body or `moduleError` for a result or refusal the module recorded, and `mutationNotSent` or `indeterminateMutation` for what reconciliation concluded. It waits for reconciliation when the mutation is still unsettled, honours cancellation and an optional timeout, and can be read repeatedly. Tracked outcomes are kept in the state store apart from the send log: a new `retained_outcome` table in `FedSQLiteStateStore` (created on open, no schema-version bump; survives a relaunch over the same directory) and the same in `FedMemoryStateStore` (process lifetime only), written in the same transactions as the intent and the terminal commit. A settled outcome is kept for at most 7 days; whenever more than 256 rows are kept, expired rows and then the oldest settled rows are removed, while pending rows are never removed and can keep the total above 256 until they settle. Result bodies are kept up to 64 KiB; a larger result throws `resultNotRetained`, and a larger refusal keeps only its code, so its `moduleError` may lack message and detail. Untracked mutations keep today's send-log pruning. `FedEffectID` gains `persistentString` and `init?(persistentString:)` (it was already `Codable`; every library-minted id round-trips) so a saved id resolves after a relaunch with `FedSQLiteStateStore`; `settledOutcome(ofPersistentString:)` throws `unknownEffect` for malformed text. `FedStateStore` gains two requirements (`reserveEffectSequenceAndCommitIntent(...retainingOutcome:)`, `retainedOutcome(of:)`) with default implementations that keep nothing, plus the public `FedRetainedOutcome` row type. Lookup failures use the new `FedSettledOutcomeError` enum (`unknownEffect`, `resultNotRetained`, `storeClosed`, `timedOut`). No existing public enum gains a case or changes associated values.

- Add `DeviceApprovalRequests.mergeList()` for `GET /v1/device/merges`, with a strict decoder returning `DeviceApprovalMergeList` (closed `DeviceApprovalMergeView` elements and an opaque string-or-null cursor) so the app can list pending account merges without tracking merge ids. Unknown, missing and duplicate members refuse; counters, versions and times must be decimal strings at most 2^53 − 1; ids must be canonical ULIDs; `state` and `automatic_hold` accept only their defined values. Any non-200 status or malformed body throws `DeviceApprovalMergeListError` (carrying the typed route refusal when there is one), never an empty list. Pin the account service's six reply vectors for both the device and machine routes and verify their vendored checksum in tests and CI. No existing public enum gains a case.

- **Breaking:** Add `FedFailure.mutationNotSent(code:message:detail:)` to the public enum. Exhaustive switches must handle the new case; the iOS app adds it in lockstep. A mutating `callManagement` settled `not_sent` (for example by `fed_busy`) now throws this case, not `moduleError`: the call provably never reached the module and is safe to send again as a new call. The settling code, message and detail are preserved for diagnostics and must not be treated as a module refusal. The new case round-trips through `Codable`.

- Mutating calls now throw module refusals like queries do. A module that refuses a mutating `callManagement` call (for example an upload chunk refused with `offset_gap`) previously returned its error envelope (`{"code":…,"message":…,"detail":…}`) as a successful body; it now throws `FedFailure.moduleError` with the module's code, message and detail, after the refusal has settled durably. What the caller receives follows the settled send-log row: a recorded outcome of kind `error` throws `moduleError`; a `not_sent` settlement throws `mutationNotSent`; an `ambiguous` settlement (for example `fed_seq_fenced`), where the module may already have received the call, throws `FedFailure.indeterminateMutation` so it is never mistaken for a retry-safe outcome. Each of these used to return the error body as success. Any other recorded outcome still returns its body. Settlement, the send-log row and permit release are unchanged, and the mutating path still carries no host-refusal hint. Pure queries still throw `moduleError` for error envelopes.
- Add a strict `DeviceCapabilitiesUpdate` reply decoder: only a `{"ok":true}` body with no additional members at HTTP 200 succeeds. Route-specific refusals retain typed codes (including unknown codes) without matching display text; malformed replies and unexpected statuses throw transport faults for the app to retry later. Pin the account service's 16 real reply vectors and verify their vendored checksum in tests and CI. No existing public enum gains a case.
- Restore saved device-approval Secure Enclave keys with `DeviceApprovalActionKey(dataRepresentation:)`, preserving the public key so registration can be repeated after relaunch with a fresh challenge. Save key data before registration; invalid references refuse with `key_restoration_failed`, and unsupported hardware/simulators still refuse with `secure_enclave_unavailable`. Fresh user presence and low-S signing are unchanged.

- Add a separate `SubcFedTestSupport` library product and `SoftwareDeviceApprovalSigner` for simulator/app tests to construct action keys and signed decision requests without `@testable import SubcFed`. Shared construction/signing seams use Swift 5.9 `package` access, not public software-key APIs or SPI in `SubcFed`; keep this product out of production app targets.

- Keep the rendezvous session and contiguous cursor alive when approval handling is not configured: discard notice presentation without persisting or acknowledging it, count unhandled deliveries, and log once per session so a later configured session can replay them.

- Refuse rendezvous control-session `seq` and `server_seq` values above 2^53 - 1 (9007199254740991), uniformly for ordinary frames and device-approval notices/acks. Other decimal-string fields keep their existing validation.

- Read all six signed device-approval/removal/merge rendezvous notice types with the account-key pin, strict closed JSON, locally recomputed comparison fingerprints/codes, contiguous cursor participation and receipt-only acknowledgements. Opt-in handling presents a card before committing its seen mark to the fed state store, then acknowledges every delivery; resolved, deadline and seven-day pruning suppress obsolete or repeated cards without an ack outbox. Add canonical capability update bodies for app-owned opt-in/out HTTP calls, a predecessor-bound signing overload with `predecessor_mismatch`, and a closed APNs wake-up hint parser that never authorizes an action. Pin and verify the rendezvous server's published notice set. No existing public enum gains a case.

- Expose `SecureEnclaveP256Signer` for purpose-separated keys and raw-byte signing, returning P1363 and DER encodings of the same low-S signature. Device-approval signing retains its checked-challenge API and delegates to this shared implementation for key creation, fresh per-signature user presence and normalization. Apps must use a separate key for vault agent-secret approvals and must never use the raw-byte primitive directly with their device-approval key.

- Decode Ed25519 points explicitly and reject weak encodings for both rosters. Apply exactly libsodium's seven-entry X25519 low-order blocklist with bit 255 masked, refusing all fourteen encodings in fingerprints and phone approval/removal challenges without a broader DH test. Pin all fourteen F/A/D refusals, weak/non-point Ed25519 keys (including machine targets), and X25519 device-id mismatch cases in shared phone vectors; keep the published rendezvous file unchanged.

- Add the complete phone approval HTTP boundary without networking: typed GET card/status/list decoders, challenge-issuance request builders and closed challenge replies, signed fixed-order decision bodies, and route-specific success/refusal decoders for approve/cancel, removal/self-revoke, merge veto, registration and possession. Treat cursors as opaque strings or null and retry delays as JSON integers. Collection reuses the existing rendezvous envelope verifier with explicit `.pinned(storedPin)` or `.firstEnrollment` trust (the app uses the latter only when no pin is stored and only for a reply fetched over authenticated HTTPS); mismatches refuse as `account_key_mismatch`, and a new pin is returned only after verification. Pin request bytes and reply cases in generated shared vectors.

- Add phone device-approval byte primitives: closed A/D/M/R/P challenge decoders, strict decimal-string and key grammars, local SHA-256 fingerprints and integer-only comparison codes, exact transcript reconstruction, a user-presence Secure Enclave P-256 signer with low-S P1363 encoding, retained-companion Ed25519 proofs, and public signature self-checks. Introduce standalone `DeviceApprovalError` with extensible string codes; no existing public enum gains a case. Add pinned rendezvous vectors, deterministic phone vectors and rejection tests, including refusal of JSON numbers in decimal-string fields. Apps retain key storage, card/context comparison, UI and networking ownership.

- Isolate malformed remote catalog entries instead of disconnecting the session: drop every copy of duplicate module IDs and modules with duplicate operation names, retain the first 64 usable management modules, and log only identifiers and drop reasons. Validate only entry fields used to build the remote catalog; ignore all other entry members, including unrestricted JSON numbers in schemas, role declarations and future fields, without weakening strict fed JSON elsewhere. No public signatures or enum cases change.
- Serialize Noise record I/O independently in each direction across carrier suspension points, keeping nonces ordered and multi-record frames contiguous. Close replaced, failed and abandoned sessions before cleanup; stop their receive/timer drivers and reject writes after closure. Deadline changes now wake one timer driver without cancelling an in-flight poll. Session-loss diagnostics name payload-free error cases and, for sessions on a Noise transport, include the next Noise send/receive nonce counters, without logging associated values, keys, addresses or frame contents. No public signatures or enum cases change.
- Drive established ordinary-session keepalive, inbound-staleness, assembly and rekey-drain timers with the injected monotonic clock. Receive-only watches now keep the connection alive, and silent peers lose their watches and reconnect. Share sessions also send idle keepalives while awaiting a result and report a silent peer's outstanding share as unknown, never refused. Cancel drivers on session teardown/replacement and log ordinary-session loss causes without frame contents, keys or addresses. The wait for a subscription's `open` remains unbounded.
- `AskRequest` decodes and encodes the optional `review`: the id of the review an ask was filed for, present only on asks filed through prefrontal-core's review tool. Every other ask decodes it as `nil`. No error cases change.
- Add optional `CatalogEntry.roleDeclarations` as a raw JSON value, preserving opaque role-owned objects from `catalog.list` without interpreting their schemas. Legacy entries leave it absent; the permissive projection and public enums are unchanged.
- Add `SubcFedClient.peerAdvertisedFeatures`: every feature the computer listed in the current session's authenticated hello, sorted, before intersecting with the phone's own list. Like `negotiatedFeatures`, it is empty until a session is ready and cleared on disconnect. Use it to decide whether a computer serves share sessions (`advertisedShareV1` in `FedShareDirectory.update`); the README previously suggested `negotiatedFeatures`, which can never contain `share-v1` because the phone's ordinary hello does not offer it, so the share extension never dialed. The negotiated set and the ordinary session's frame checks are unchanged. `FedNegotiatedSession` and `FedSessionEngine` gain the same list; no public enum changes.
- **Breaking:** `FedFailure.moduleError` gains a fourth associated value, `detail: FedJSONValue? = nil`, preserving the module's JSON error context from terminal call frames (absent or JSON null detail becomes nil). Labelled constructions remain source-compatible. Update positional matches from `.moduleError(let code, let message, let hostRefusal)` to `.moduleError(let code, let message, let hostRefusal, let detail)` (or use `_` for the fourth value if unused). Persisted failures without the detail key still decode.

- Advertise and negotiate `framed-calls-v1`, parse operation-local `payload.max_bytes` in negotiated catalogs, and add `SubcFedClient.callManagement(target:method:params:payload:)`. Unsupported sessions, undeclared payloads and oversized payloads fail locally before admission or writes. Add standalone `FedFramedCallError`, `FedFramedBodyError`, `FedOperationPayload`, and `FedFramedBodyCodec`, plus `FedCatalogOperation.payload`; no existing public enum gains cases. The codec shares `vectors/framed-body-v1` with Rust.
- Bound share-ledger retention to 30 days of UUIDv7 creation times. Persist SHA-256 request digests and outcome metadata without payload bodies; return full result bodies only to the caller. Old pending ids fail closed as unknown even after pruning, never becoming fresh share or outbox work. Use one compact version-1 file format and document the app's Edit/Delete treatment of expired shares.
- Add direct-only `FedShareClient` sessions alongside the app's ordinary session, with share-only result types, closed share frame shapes, a durable per-transaction App Group `FedShareLedger` (claims, immutable bindings, newest-answer fencing and synchronous outbox moves), and a library-written atomic `FedShareDirectory` snapshot. Preserve existing public enum cases. Cover every disposition, binding changes, serial/eight-call/lifetime limits and bye codes, plus real-process contention and killed-holder lock release.
- Give `FedSQLiteStateStore` exclusive, non-blocking ownership from open to explicit `close()` (with a deinit backstop), including across app/extension processes. A competing opener throws the new public `FedStateStoreInUse` error without accessing SQLite. Close is terminal for the actor: later opens, reads and writes throw `FedStateStoreClosed`, as do clients retaining it; use a new store and new clients for the next ownership period over the same disk state. No existing public enum gains a case. Document shared-client shutdown and App Group handoff, with same-process, cross-process and close/handoff coverage.
- Add optional `richUi` catalog descriptor metadata and `nonceVerified`; catalog decoding remains a permissive JSON projection, and legacy entries leave both fields absent.
- Add `MAX_DELIVERED_FRAME_LEN` (4,194,304 bytes, header included), mirroring subc-protocol 0.32.9: the largest frame the daemon delivers from a module to a client. A larger module frame is never forwarded. `ProtocolConstantsTests` checks it against the Rust fixture.
- Decode the optional registry-row `capabilities` list only when it contains at most eight unique, byte-sorted tokens matching `^[a-z][a-z0-9-]{0,31}$`; expose the list on `RdvRegistryRow`. `servesFed` is true when the list contains `fed-serve`, meaning the computer says it accepts direct connections from paired devices. It is a routing hint only: it does not authenticate a peer or grant access, and a device still connects only to computers it has paired with.

- Add coverage verifying that two live clients for different peers can share one SQLite store without mixing peer state, and that concurrent callers sharing the actor assign unique, durable sequence numbers to every mutation. Separate same-path store instances must hand off exclusive ownership.

- `BoardLaneWait` decodes the optional `lastIdleTransitionMs`, accepting `lastIdleTransitionMs` or `last_idle_transition_ms`: the board owner's most recent idle transition, repeated on each wait and absent when the owner has no turn anchor. A held board uses it to age a wait's `rotten` verdict while the server answers `unchanged`. It is encoded only when present, and the memberwise initializer gains a defaulted parameter, so existing call sites compile unchanged.
- `AskRequest` decodes the optional `headAgentId` (spelled with a lowercase d, exactly as the producer writes it): the lead agent of a worker's ask, resolved by the producer from the verified scope chain. A head's own ask has no such key and decodes as `nil`. It is for placing the ask under its lead agent and confers no approval authority. No error cases change.
- Add `ScopeBindProofCodes.required` and `.mismatch`, the daemon's two refusal codes for a scoped route open that is missing its scope's bind proof or carries the wrong one. Callers receive them as `FedFailure.moduleError` with a readable message, the same case other terminal refusals use, so no public SubcFed enum gains a case and existing exhaustive switches keep compiling. Both codes are terminal (`crates/subc-protocol/tests/golden/decision_tables.json`): never retry the open.

- `BoardLaneItem` decodes four optional fields: `etaMs`, `changedAtMs`, `followUp` and `noteRef`. Each accepts the snake_case wire spelling or the camelCase spelling after key normalization, like the other lane types. Items without them decode as before.
- Expose module-declared bus events on `CatalogEntry`, preserving the manifest declaration shape returned by `catalog.list`.
- Add golden-reply regressions for `scope.describe` so run deadlines (`scope.expires_at_ms`) and future stamp fields stay readable through `callManagement`, while legacy replies without a deadline remain supported. The client already returns reply dictionaries without restricting their keys.
- The new `call_mode` field identifies classic, codemode or flow calls on provider-side `route.bind` messages. This package opens routes as a client rather than accepting provider binds, so there is no Swift bind decoder to update.
