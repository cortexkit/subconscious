The CortexKit Landscape

SUBC: the multiplexed splice-router

The per-user ck-subc daemon supervises CortexKit modules and routes their traffic by reading a fixed 21-byte WIRE v2 header. Payload bodies remain opaque.

Shipped outcome. AFT is a subc consumer in production. Tool traffic moved off the retired NDJSON lane, so independent calls can run concurrently through supervised routes instead of queueing behind one stream.

The thin-core bet

SUBC reads only the envelope header to route opaque payloads. A new module declares a manifest and speaks the wire without adding module-specific parsing to the daemon. Channel 0 carries control RPCs; non-zero routes use independent client-side and module-side channel spaces.

Fleet binaries follow the ck-* naming convention. The ck operator CLI covers module list, status, restart and rescan, health with a per-module fresh-probe detail verb, quota, and daemon operations. The daemon also self-watchdogs with a 60-second loopback self-probe and connection-file integrity check, and raises file-descriptor limits for its children.

Wire Contract · WIRE v2

The 21-byte envelope

Every frame starts with this fixed little-endian header. The first five bytes, len plus the version byte location, remain the frozen prefix. All following fields are the version-2 layout.

Exact-match tripwire. The version byte is exactly 2. There is no negotiation: a v2 binary talking to a v1 daemon fails loudly on its first frame.

Data Flows

Three paths through the daemon

Connection, binding, and invocation stay separate so authentication and route ownership can be checked before opaque traffic moves.

1

Connect and authenticate

connection file → client nonce
server proof first → client proof
channel 0 live

The proofs use domain-separated HMAC-SHA256. The client sends no proof until it validates the server.

2

Open and bind a route

route.open → canonical root
consumer_identity → route.bind
on_bind / on_bound → (channel, epoch)

The daemon canonicalizes with cortexkit-paths. Spawn nonces resolve to Principal reserved:<id>; direct consumers are also validated. The module decides in on_bind, then on_bound may emit.

3

Call a tool

client channel → header rewrite
opaque body → module channel
response → reverse rewrite

Only the channel header changes between independent spaces, with zero body parsing. The reverse-request lane runs module-to-client on the same route without consuming forward credits.

The body is not a routing input. Authentication establishes the connection, binding establishes the route, and the 21-byte header is enough to splice traffic in both directions.
Transport & Auth

A local, authenticated boundary

SUBC listens only on loopback TCP and publishes connection material through a user-owned 0600 file.

BoundaryMechanism
SingletonAn advisory start lock prevents competing daemons.
HandshakeServer-proves-first, domain-separated HMAC-SHA256 before channel 0 opens.
Pre-auth budgetsA bounded queue-wait budget plus a fresh handshake deadline keep restart herds from creating false handshake timeouts.
Spawn attestationEvery daemon-spawned module receives a launch nonce; route.open validates the presented consumer identity against it.
Self-watchdogA 60-second loopback self-probe checks service health and connection-file integrity.
Two clocks, two meanings. Queue pressure is measured separately from the fresh handshake deadline. A valid process waiting behind a restart herd does not spend its authentication time budget before it reaches the handshake.
Storage

Isolation by module and path

Each module owns a path-scoped SQLite database under ~/.local/share/cortexkit/<module>/. Modules do not receive a fleet-wide database handle.

One writer means two guards. cortexkit-lease combines an OS-level single-writer lock with an epoch-CAS fence. Cross-language golden vectors keep Rust and TypeScript storage behavior aligned.
Multi-Auth

The vault is the login root

ck auth login runs vault-native OAuth flows. The vault owns crash-safe token rotation and its audit chain instead of delegating credential custody to a provider client.

Provider methodHow broca uses it
oauthVault-managed access and refresh credentials.

Handles, not raw secrets. Credential handles are capability tokens. Never-strand fallback keeps a usable provider path available when a preferred account or method cannot serve a run.
